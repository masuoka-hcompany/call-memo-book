## 1. 概要

### 1.1 一言でいうと
受電者が、会社・担当者ごとに登録された宛先ごとの「取次可否（つなぐ/つながない）」を見て取次ぎを判断し、取次メモ（用件・伝言）を残せるアプリ。宛先は自分宛ての取次メモを確認し、対処済みにできる。

### 1.2 背景・解決したい課題
- 宛先ごとに「つなぐ/つながない」の方針が違うが、受電者がそれを覚えておけない
- 取次ぎのたびに、受電者が宛先のところまで走って行き「〇〇さんから電話です」と口頭で伝えており、そのやり取りにコストがかかっている
- 現在の取次ぎ手段は DM・Slack チャンネルでのメッセージ、口頭（走って伝える）、内線でつなぐ、のいずれか。このうち DM・Slack チャンネルでのメッセージをアプリで置き換える

### 1.3 ゴール（このSTEPで達成したい状態）
- 受電者が、相手の会社名・担当者名・電話番号から、宛先ごとの取次可否をアプリ上で確認できる
- 「つながない」相手からの電話は、走って伝えに行かずに、取次メモを残すだけで済む

### 1.4 対象ユーザー
社員は全員「受電者」になる。「宛先」「管理者」は、受電者に加えて持つ役割とする。

| ユーザー種別 | 説明 | 主な利用シーン | できること / できないこと |
|---|---|---|---|
| 受電者 | 社員全員（`h-company.co.jp` の Google アカウントを持つ人）。誰でも受電者になりうる | 電話を受けたとき | **できる**：会社・担当者の登録・編集・削除（論理削除）／取次可否の設定（他人の代理での設定を含む）／取次メモの作成／取次メモの一覧・検索・閲覧（他人宛てのものを含む）／自分が作成した取次メモの編集・削除<br>**できない**：他人が作成した取次メモの編集・削除／取次メモを対処済み・未対処にする操作／宛先の追加・編集・削除／削除したデータの画面からの復旧 |
| 宛先 | 取次ぎを受ける人。当初は社長・菊地さん・益岡・木村さん。管理者がアプリ上で追加する | 自分宛ての取次メモを確認するとき | **できる**：受電者ができることすべて／自分宛ての取次メモを対処済みにする、未対処に戻す<br>**できない**：他人宛ての取次メモを対処済み・未対処にする操作／宛先の追加・編集・削除 |
| 管理者 | 未定（開発チームのメンバーは含める想定） | 宛先を管理するとき | **できる**：受電者ができることすべて／宛先の追加・編集・削除（論理削除）<br>**できない**：上記以外の特別な操作（他人が作成した取次メモの編集・削除、管理者の任命、削除データの復旧など）。運用上必要になれば追加する |

- 会社・担当者・取次可否・宛先・取次メモについて、誰が更新したかを記録する（取次メモの更新者は画面に表示しない）

## 2. スコープ

### 2.1 やること
1. 会社・担当者の登録・編集・削除（論理削除）。1つの会社に複数の担当者が紐づく
2. 宛先ごとの取次可否の設定（会社単位・担当者単位）
3. 受電時に、会社名・担当者名・電話番号で相手を検索し、宛先ごとの取次可否を確認する
4. 取次メモの作成・編集・削除
5. 取次メモの一覧・検索
6. 取次メモを対処済みにする／未対処に戻す（宛先本人のみ）
7. 宛先の追加・編集・削除（論理削除。管理者のみ）
8. 会社・担当者・取次可否・宛先・取次メモの更新者の記録

### 2.2 やらないこと
- 工事士com の営業チーム宛ての取次ぎ
- Slack 通知（STEP2 で扱う）
- 着信記録の自動連携（STEP2 で扱う）
- 口頭・内線でつなぐこと自体（アプリは取次可否の確認と取次メモの記録のみを担う）
- 削除したデータを画面から復旧すること（エンジニアが DB を操作して復旧する）
- 管理者を任命する機能

### 2.3 前提条件・制約
- 対応環境は PC のみ（Windows 11、Mac）。ブラウザは Chrome、Edge
- ログインは Google アカウントで行う。`h-company.co.jp` ドメインのアカウントなら誰でもログインでき、初回ログイン時に利用者として登録される（Cloudflare Access で実現する。9章）
- STEP1 では通知がないため、宛先は自分でアプリを開き、一覧で自分宛ての取次メモを確認する
- 「つなぐ」相手につなげた場合は、取次メモを残さない。取次メモを残すのは、「つなぐ」相手だが離席などでつなげなかった場合と、「つながない」相手から電話があった場合（電話があった記録として）
- 削除はすべて論理削除とする。復旧はエンジニアが DB を操作して行う
- 技術スタックは9章のとおり

## 4. 主なユースケース

### UC-01：受電時に相手を検索し、宛先ごとの取次可否を確認する
- 利用者：受電者
- 流れ：
  1. 受電者が、相手から聞いた会社名・担当者名・電話番号のどれかで検索する
  2. システムが、該当する会社・担当者を検索結果として、電話番号・担当者名とあわせて表示する（同じ会社名の別の会社を見分けられるようにするため）
  3. 受電者が相手を選ぶ
  4. システムが、宛先ごとの取次可否（つなぐ/つながない/未設定）を表示する
  5. 受電者が、取次可否を見て、内線でつなぐか、断る（または離席中と伝える）かを判断する
- 備考：同じ会社名の別の会社に「つながない」を設定した場合に、違う会社の電話まで断ってしまうことを避ける

### UC-02：取次メモを作成する
- 利用者：受電者
- 流れ：
  1. 「つなぐ」相手だが離席などでつなげなかった場合、または「つながない」相手から電話があった場合に、受電者が取次メモの作成を始める
  2. 登録済みの相手（UC-01 で選んだ相手）の場合、システムが会社名・氏名・電話番号を自動で入れる。未登録の相手の場合、受電者が会社名・氏名・電話番号を手で入力する（会社・担当者としては登録しない）
  3. 受電者が宛先・用件・伝言・メモを入力して保存する
  4. 取次メモが保存され、一覧に表示される

### UC-03：自分宛ての取次メモを確認し、対処済みにする
- 利用者：宛先
- 流れ：
  1. 宛先がアプリを開き、取次メモの一覧で自分宛ての取次メモを確認する
  2. 宛先が、必要な対応（折り返しなど）を終えるか、対応が不要と判断したら、その取次メモを対処済みにする
  3. 取次メモが対処済みになる
  4. 間違えて対処済みにした場合、宛先は未対処に戻せる

### UC-04：取次メモを編集・削除する
- 利用者：取次メモを作成した人
- 流れ：
  1. 作成者が、自分が作成した取次メモを開く
  2. 作成者が内容を編集して保存する、または削除する
  3. 取次メモが更新される、または一覧に表示されなくなる（論理削除）

### UC-05：会社・担当者を登録・編集・削除する
- 利用者：受電者（全員）
- 流れ：
  1. 利用者が会社を登録する（会社名・会社名のよみがな・メモ）
  2. 利用者が、その会社に担当者を登録する（担当者名・担当者名のよみがな・電話番号・メモ）。1つの会社に複数の担当者を登録できる
  3. 利用者は、登録済みの会社・担当者を編集・削除（論理削除）できる
  4. システムが更新者を記録する

### UC-06：取次可否を設定する
- 利用者：受電者（全員。宛先本人に代わって設定する場合を含む）
- 流れ：
  1. 利用者が会社または担当者を選ぶ
  2. 利用者が、宛先ごとに取次可否（つなぐ/つながない/未設定）を設定する
  3. システムが設定と更新者を記録する

### UC-07：宛先を追加・編集・削除する
- 利用者：管理者
- 流れ：
  1. 管理者が宛先を追加する
  2. 管理者は、登録済みの宛先を編集・削除（論理削除）できる
  3. システムが更新者を記録する

### UC-08：取次メモを一覧・検索する
- 利用者：受電者（全員）
- 流れ：
  1. 利用者が取次メモの一覧を開く
  2. 利用者が条件を指定して検索する
  3. システムが条件に合う取次メモを表示する（他人宛てのものを含む）

### UC-09：初めてアプリを使う
- 利用者：社員（`h-company.co.jp` の Google アカウントを持つ人）
- 流れ：
  1. 社員がアプリの URL を開く
  2. Cloudflare Access が Google アカウントで認証する（社外のアカウントはここで拒否される）
  3. システムが、初回であればその社員を利用者として登録する
  4. S-01 相手検索が表示され、アプリを使い始められる

## 6. 機能詳細

### F-01：相手の検索・取次可否の確認
| 項目 | 内容 |
|---|---|
| 目的 | 受電時に相手を特定し、宛先ごとの取次可否を確認して、つなぐかどうかを判断できるようにする |
| 利用者 / 利用権限 | 受電者（全員） |
| 操作の流れ | 1. 検索欄に入力して検索する → 2. 検索結果が表示される → 3. 相手を選ぶ → 4. 宛先ごとの取次可否が表示される → 5. 必要なら「取次メモを作成」を押して F-02 に進む |
| 入力 | 検索キーワード（検索欄は1つ） |
| 処理ルール | ・会社名、会社名のよみがな、担当者名、担当者名のよみがな、電話番号のいずれかに部分一致する相手を表示する<br>・会社名（よみがな）に一致した場合は、その会社の担当者全員を表示する<br>・担当者が登録されていない会社は、会社名だけの行として表示する<br>・削除された会社・担当者は表示しない<br>・検索欄が空のまま検索した場合は、検索しない<br>・検索結果の並び順は指定なし |
| 出力・表示 | ・検索結果：1行に会社名、担当者名、電話番号を表示する（担当者ごとに1行）<br>・相手を選んだあと：宛先ごとに「会社の取次可否」と「担当者の取次可否」を並べて表示する（Q-05 が決まるまでの暫定）。会社だけの行を選んだ場合は、会社の取次可否だけを表示する。削除された宛先は表示しない<br>・「取次メモを作成」ボタン（押すと F-02 の作成画面が開き、会社名・氏名・電話番号が自動で入る） |
| エラー・例外 | ・検索結果が0件：「該当する相手が見つかりません」と表示し、「取次メモを作成」ボタンを表示する（押すと F-02 の作成画面がすべて空欄で開く） |
| 受け入れ条件 | AC-01, AC-02, AC-03, AC-04, AC-35, AC-44, AC-45, AC-46, AC-47, AC-48 |
| 備考 | 同じ会社名の別の会社を、電話番号・担当者名で見分けられるようにするため、検索結果に3項目を並べて表示する |

### F-02：取次メモの作成
| 項目 | 内容 |
|---|---|
| 目的 | つなげなかった電話、または「つながない」相手からの電話を記録する |
| 利用者 / 利用権限 | 受電者（全員） |
