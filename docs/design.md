# デザインのルール（call memo book（仮）モック）

画面（S-01〜S-11）を作るときは、このファイルに従う。迷ったら「色を足さない・飾りを足さない」を選ぶ。

- 実装：`src/styles/app.css`（テーマと部品のクラス）、`src/views/Document.tsx`（CSS・JS の読み込み）
- 見本：`/__styleguide`（`MOCK_MODE=true` のときだけ。各部品の見た目はここと同じにする）
- 文言は `docs/spec.md` のとおり（CLAUDE.md）。このファイルの文言の例も、仕様書にあるものだけを使っている

## 1. 方針

- ディーター・ラムス／ブラウン製品の考え方に寄せる。画面の大部分は無彩色にし、色は**機能（状態と重要な操作）にだけ**使う
- 影・グラデーション・角丸は使わない。区切りは細い線と余白で作る
- 色だけで意味を伝えない。状態は必ず「**色＋記号＋文字**」で示す（例：「✕ つながない」「● 未対処」）
- WCAG 2.2 AA を満たす（文字 4.5:1、UI 部品の境界 3:1）。計算結果は末尾の「付録：コントラスト比」

## 2. パレット

**これ以外の色は使わない。** Tailwind の色のクラス（`text-gray-500`、`bg-blue-100` など）や、任意の値（`text-[#333]`）も使わない。

| 役割 | 色 | 用途 | 使うクラス |
|---|---|---|---|
| 面 | `#FAFAF8` | ページ背景 | `bg-base-100` |
| 区画 | `#F0F0EC` | 選択中の行、完了メッセージの背景、disabled の入力欄 | `bg-base-200`（行・メッセージは下の専用クラス） |
| 押せる面 | `#E6E6E1` | 補助ボタン（hover は `#DCDCD7`） | `btn-quiet` |
| 線 | `#DCDCD7` | 行区切り、ヘッダー下の線、ダイアログの枠、disabled の枠 | `border-base-300` |
| フォーム枠 | `#8A8A84` | 入力欄の通常時（入力欄の中は `#FFFFFF`） | `input`・`select`・`textarea` |
| 補助 | `#6B6B66` | 補足の文字、ラベル、採用されない値、未選択のメニュー、フォーム枠の hover、未設定の破線枠 | `text-secondary` |
| 黒 | `#1C1C1B` | 本文、「つながない」の塗り（黒の塗りはこれ専用）、通常ボタンの枠と文字、focus、見出しの線、現在地の下線 | `text-base-content`・`border-base-content` |
| 赤 | `#C2361F` | 主要ボタン（1画面1つ）、ロゴの点、入力エラーの枠と文字。**赤はこの1色だけ** | `btn-primary`・`input-error`・`error-text`・`bg-primary`（ロゴの点だけ） |
| 緑 | `#2B784C` | 「つなぐ」、完了メッセージの左の線 | `verdict-ok`・`flash-done` |
| 黄 | `#F1CE3C`（文字 `#4A3B05`） | 【未決】バッジ（**モック専用。本番では使わない**） | `badge badge-warning` |

- `#FFFFFF` は、入力欄の中、通常ボタンの面、色の塗りの上の文字にだけ使う
- 黒の塗りは「つながない」専用。ほかの場所（ボタン、バッジ、メニュー、見出し）を黒で塗らない
- daisyUI のテーマ `rams-a` は、`<html data-theme="rams-a">` で有効にする（`Document.tsx` が付ける）

## 3. フォント

- Noto Sans JP（Google Fonts）。`app.css` の先頭で読み込む
- 太さは **400 と 700 の2種類だけ**。700 は次の場所にだけ使う
  - 宛先名、判定、現在地のメニュー、主要ボタン、未対処
  - 例外：画面の見出し（h1・h2）と、内訳の採用された値（`source-adopted`）
- 電話番号・日時には `tabular`（等幅数字）を付ける
- 文字の大きさは daisyUI と Tailwind の標準（`text-sm` など）から選ぶ。小さい文字は `text-sm`（0.875rem）を下限にする

## 4. 部品のルール

### 4.1 使わない daisyUI のクラス

黒い塗り・影・色が出るため、次のクラスは使わない。

| 使わない | 代わりに使う |
|---|---|
| `btn-neutral`・`btn-accent`・`btn-secondary`・`btn-info`・`btn-success`・`btn-warning`・`btn-error`、無指定の `btn` | `btn-primary`（主要）・`btn-plain`（通常）・`btn-quiet`（補助） |
| `badge-neutral`・`badge-accent`・`badge-primary` などの色付きバッジ | 状態は文字と記号で示す（4.8）。バッジは【未決】の `badge-warning` だけ |
| `menu-active`・`tabs-box`・`tab-active` の塗り | メニューは `nav-item`（4.6） |
| `alert`（`alert-success` など） | 完了メッセージは `flash-done`（4.7） |
| `shadow-*`・`rounded-*`・`bg-gradient-*` | 使わない（線と余白で区切る） |
| `input-lg` 以外の大きさの指定（`input-sm` など） | 標準の大きさ。S-01 の検索欄だけ `input-lg` |

### 4.2 入力欄

- `input`・`select`・`textarea` を使う。枠は `#8A8A84`、中は `#FFFFFF`
- hover：枠を補助グレー `#6B6B66` にする
- 入力中：枠を黒にし、内側に 1px 足して 2px の単線に見せる（`box-shadow: inset`）。外側の二重線（daisyUI の outline）は出さない
- S-01 の検索欄だけ `input-lg` で一回り大きくする。形と色はほかの入力欄と同じ
- 項目名は入力欄の上に置き、`<label>` で入力欄とつなぐ。項目名はエラーメッセージの {項目名} と同じ（CLAUDE.md）
- ブラウザの入力チェックは使わない（`<form novalidate>`。`required`・`maxlength`・`pattern` を付けない）

### 4.3 入力エラー

- エラーの欄に `input-error`（`select-error`・`textarea-error`）と `aria-invalid="true"` を付ける。枠を赤にする
- hover や入力中でも赤い枠を保つ（入力中は赤の 2px の単線）
- エラーメッセージは入力欄のすぐ下に `error-text` で表示する（赤の文字、`text-sm`）。文言は仕様書のとおり
- 1つの欄に複数のエラーがあるときは、すべてを1行ずつ並べる（`docs/questions.md` Q-M09）
- エラーの欄とメッセージは `aria-describedby` でつなぐ

### 4.4 disabled

- 入力欄：面を区画 `#F0F0EC`、枠を線 `#DCDCD7`、文字を補助グレーにする（有効な欄と見分けるため）
- ボタン：daisyUI の disabled の見た目（薄い面と薄い文字）のまま。主要・通常・補助の色は付けない

### 4.5 ボタン

ボタンは3種類だけ。

| 種類 | クラス | 見た目 | 使う場所 |
|---|---|---|---|
| 主要 | `btn btn-primary` | 赤の塗り・白文字・太字 | **1画面に1つ**。その画面のいちばん大事な操作（例：S-01 の「取次メモを作成」、入力画面の「保存」） |
| 通常 | `btn btn-plain` | 白の面＋黒枠＋黒文字 | そのほかの操作（例：「編集」「削除」「対処済みにする」、S-01 の「検索」） |
| 補助 | `btn btn-quiet` | `#E6E6E1` の面・枠なし | 取り消し・戻る系（例：確認ダイアログの「キャンセル」） |

- 主要ボタンの文字は 700。通常・補助は 400
- 削除は、確認ダイアログが付くので赤にしない（通常ボタン）
- ボタン・リンク・タブの focus は 2px の黒い outline（offset 2px）。`app.css` が付けるので個別に指定しない

### 4.6 メニュー（ヘッダー）

- ヘッダーは、左にロゴ（赤の四角の点＋「call memo book（仮）」）とメニュー、右にログイン中の利用者名とモック用の切替を置く。下に線 `#DCDCD7`
- メニューは `nav-item`。現在地には `aria-current="page"` を付ける（黒の太字と 2px の黒い下線）。それ以外は補助グレー
- メニュー名は仕様書のとおり：相手検索／取次メモ一覧／会社一覧／宛先一覧
- 「モック用：ログインユーザー切替」は、黄の破線枠と薄い黄の面で囲み、仕様の画面要素と区別する（モック専用）

### 4.7 完了メッセージ

- `flash-done`：区画 `#F0F0EC` の面、黒文字、左に緑の 3px 線。`role="status"` を付ける
- 置き場所は、画面の見出しの下・本文の上

### 4.8 一覧と表

- 行の区切りは `border-b border-base-300` の細い線だけ。縞模様（`table-zebra`）や縦線は使わない
- 列見出しは補助グレー・400・`text-sm`
- 検索結果の選択中の行：`row-selected`（区画 `#F0F0EC` の面と、左に黒の 3px 線）。行のリンクに `aria-current="true"` を付ける
- 取次メモの状態
  - 未対処：`status-open` で「● 未対処」（黒の太字）
  - 対処済み：`status-done` で「✓ 対処済み」（補助グレー）

### 4.9 確認ダイアログ

- daisyUI の `modal`（`<dialog>`）を使う。枠は `#DCDCD7`、影なし（`app.css` で指定済み）
- 文言は仕様書のとおり（例：「この会社を削除しますか？ 所属する担当者も削除されます」）
- ボタンは「キャンセル」＝補助、「削除する」＝通常。並びは左が「キャンセル」、右が「削除する」
  - 「キャンセル」は `LABELS.cancel`（`src/views/labels.ts`）を使う。ボタン名は仕様書に書かれていないため仮の形（`docs/questions.md` Q-M03）

### 4.10 【未決】バッジ（モック専用）

- `badge badge-warning` で「【未決】Q-Mxx 〜」と表示する。ID は `docs/questions.md` と同じ
- 未決の部品の近く（上か右）に置く。本番では使わない

### 4.11 モック専用の表示

- ログインユーザー切替と、まだ作っていない画面の仮のページの表示は、黄の破線枠と薄い黄の面（`MockBox`：`border border-dashed border-warning bg-warning/20`）で囲む。Tailwind と daisyUI の標準のクラスだけで作り、`app.css` には足していない
- 文言は `src/views/labels.ts` の `MOCK_LABELS`

### 4.12 部品の置き場所

画面からは次の部品を使い、同じ見た目をその場で作り直さない（`/__styleguide` も同じ部品で表示している）。

| 部品 | 置き場所 |
|---|---|
| ヘッダー（メニュー・ログイン中の利用者名・ログインユーザー切替）、画面の見出し、完了メッセージの位置 | `src/views/AppLayout.tsx`（画面は `src/routes/page.tsx` の `renderPage` で返す） |
| 完了メッセージ、「削除」ボタンと確認ダイアログ、【未決】バッジ、モック専用の枠 | `src/views/components.tsx`（`FlashMessage`・`DeleteButton`・`PendingBadge`・`MockBox`） |
| 完了メッセージ・確認ダイアログの文言 | `src/views/messages.ts` |

- ヘッダーは PC の幅（1,024px）でも折り返さない（`whitespace-nowrap`）

## 5. S-01 の取次可否の表示（判定列）

【未決】判定列を設けることは画面構成の変更にあたるため、レビュー会で決める（`docs/questions.md` Q-M01）。画面には「【未決】Q-M01 採用値の強調（判定列）」のバッジを付ける。

### 5.1 形

宛先ごとに1行で「**宛先｜判定｜内訳**」の3列にする。

| 宛先 | 判定 | 内訳 |
|---|---|---|
| 菊地（太字） | 採用される値（枠か塗り） | 担当者：〇〇　／　会社：〇〇 |

### 5.2 判定（採用される値）

3種類とも同じ大きさの枠（`verdict`：min-width 9.5em、枠 2px、太字）で表示する。

| 値 | クラス | 見た目 | 文字 |
|---|---|---|---|
| つながない | `verdict verdict-ng` | 黒の塗り、白文字 | `✕ つながない` |
| つなぐ | `verdict verdict-ok` | 緑の枠、緑文字 | `● つなぐ` |
| 未設定 | `verdict verdict-unset` | 補助グレーの破線枠、黒文字 | `― 未設定` |

- **採用値には必ず枠か塗りがある、を唯一のルールにする。** 会社も担当者も未設定のときも、判定列に破線枠が出る
- 採用値は優先ルール（仕様書 3章）で決める：担当者が「未設定」以外なら担当者、「未設定」なら会社。計算は `src/domain/` に置き、画面では計算しない

### 5.3 内訳

- `source-value`（0.875rem・補助グレー）で「担当者：〇〇　／　会社：〇〇」と表示する。区切りは全角スペース＋「／」＋全角スペース
- 内訳には記号（✕・●）を付けない
- 採用された方だけ `source-adopted`（黒の太字）にし、「← 採用」を添える。採用されない方は補助グレーのまま

### 5.4 4つの組み合わせ

| 組み合わせ | 担当者 | 会社 | 判定 | 内訳 |
|---|---|---|---|---|
| 両方未設定 | 未設定 | 未設定 | ― 未設定（破線枠） | 担当者：未設定　／　**会社：未設定 ← 採用** |
| 会社のみ設定 | 未設定 | つながない | ✕ つながない（黒の塗り） | 担当者：未設定　／　**会社：つながない ← 採用** |
| 担当者のみ設定 | つなぐ | 未設定 | ● つなぐ（緑の枠） | **担当者：つなぐ ← 採用**　／　会社：未設定 |
| 両方設定で逆 | つなぐ | つながない | ● つなぐ（緑の枠） | **担当者：つなぐ ← 採用**　／　会社：つながない |

- 採用値が「未設定」のときに受電者がどう対応するかは決まっていない（仕様書 Q-11、`docs/questions.md` Q-M02）。画面は「未設定」とそのまま表示するだけにし、案内の文言は足さない

## 6. CSS・JS の読み込み（ビルドしない）

- Tailwind は `@tailwindcss/browser`、daisyUI は CDN 版の `daisyui.css` を、バージョンを固定して読み込む（`src/views/Document.tsx` の `CDN`）
- `src/styles/app.css` は Worker が `/styles/app.css` として返す（`wrangler.jsonc` の `rules` でテキストとして読み込む）
- daisyUI の CDN 版はすべて `@layer` の中にある。`app.css` はレイヤーに入れていないので、詳細度にかかわらず `app.css` の規則が優先される
- テーマは daisyUI の `@plugin "daisyui/theme"` ではなく、`[data-theme="rams-a"]` の CSS 変数で定義している（ビルドしないため。値は同じ）
- 新しい部品の見た目が必要になったら、まず daisyUI と Tailwind の標準のクラスで作る。足りないときだけ `app.css` にクラスを足し、このファイルと `/__styleguide` にも足す

## 7. 確認結果

`/__styleguide` を Playwright（Chromium）で開き、computed style と実際の hover・クリック・Tab の操作で確かめた。「（見本）」の部品は疑似状態を固定したものなので、判定には通常の部品を使った。

| 確認日 | 項目 | 結果 | 確かめたこと |
|---|---|---|---|
| 2026-11-11 | `app.css` の上書きが daisyUI より優先されるか | 問題なし | `.btn` の太さが 400（daisyUI は 600）、`.btn-primary` は 700。`btn-plain` は面 `#FFFFFF`・枠と文字 `#1C1C1B`、`btn-quiet` は面 `#E6E6E1`・枠なし。入力欄は面 `#FFFFFF`・枠 `#8A8A84`。角丸はすべて 0、`.modal-box` の影は none。daisyUI の `box-shadow`（ボタン・入力欄）は残るが、`--depth: 0` のためすべて透明 |
| 2026-11-11 | エラー欄で、hover 中・入力中も赤い枠が消えないか | 問題なし | 通常・hover 中は枠 `#C2361F`。入力中（クリックして focus）は枠 `#C2361F` と内側 1px の `#C2361F`（2px の単線）。focus したままマウスを外しても同じ。比較として、通常の欄は hover で `#6B6B66`、入力中は黒の 2px |
| 2026-11-11 | disabled の入力欄・ボタンが、有効なものと見分けられるか | 問題なし | 入力欄：面 `#F0F0EC`・枠 `#DCDCD7`・文字 `#6B6B66`（有効な欄は面 `#FFFFFF`・枠 `#8A8A84`）。ボタン：3種類とも daisyUI の disabled（面は黒 10%、文字は黒 20%、枠なし）になり、赤の塗り・黒枠がなくなる。補助ボタンは面の色がほぼ同じ（`#E6E6E1` と約 `#E4E4E1`）だが、文字が薄くなるので見分けられる |
| 2026-11-11 | Tab で移動したとき、すべての部品で focus が見えるか | 問題なし | Tab で巡回した 23 個（メニューのリンク4、ログインユーザー切替のプルダウン、検索欄と「検索」、入力欄・エラー欄・プルダウン・複数行、主要・通常・補助ボタン、検索結果のリンク、確認ダイアログのボタン）すべてで `:focus-visible` が効いた。リンクとボタンは黒 2px の outline（offset 2px）、入力欄とプルダウンは内側 1px を足した 2px の枠（エラー欄は赤） |
| 2026-11-11 | Noto Sans JP が読み込まれているか | 問題なし | `document.fonts` で Noto Sans JP の 400 と 700 が loaded。`document.fonts.check()` も両方 true。`body` の font-family の先頭が "Noto Sans JP" |

- 修正した CSS：なし
- コンソールのエラーは `/favicon.ico` の 404 だけ（見た目には関係しない）

## 付録：コントラスト比

WCAG 2.x の相対輝度の式で計算した（小数第3位を切り捨て）。基準は、文字が 4.5:1（1.4.3）、UI 部品の境界と状態を示す図形が 3:1（1.4.11）。
